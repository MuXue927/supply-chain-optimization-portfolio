# Portfolio experiment results

This folder holds the committed, curated experiment results for the two
delivery-optimization projects. It is meant to be the fastest way for a reader
to see what the project does and how well it works.

Raw per-run directories and console logs live under `results/*/raw/` and are
intentionally **not** committed (see the repository `.gitignore`). What is
committed here is the small set of summary tables and figures below.

## Contents

| Path                                   | What it is                                                               |
| -------------------------------------- | ------------------------------------------------------------------------ |
| `multi-period/runs.csv`              | One row per (instance, ALNS variant) run of the fixed multi-period ALNS. |
| `multi-period/summary.csv`           | Per-scale aggregate statistics.                                          |
| `multi-period/thesis_reference.csv`  | The thesis ALNS numbers on the identical instances.                      |
| `multi-period/comparison.csv`        | New ALNS versus thesis ALNS side by side.                                |
| `multi-period/figures/`              | New-versus-thesis figures.                                               |
| `single-period/runs.csv`             | Heuristic and CPLEX Python API runs for the single-period project.       |
| `single-period/thesis_reference.csv` | The thesis Gurobi incumbents for reference.                              |
| `single-period/comparison.csv`       | Heuristic, CPLEX, and thesis side by side.                               |
| `single-period/figures/`             | Single-period comparison figure.                                         |

## Instance set

Five instances per project cover three scales (2 small, 2 medium, 1 large).
The multi-period instances are the thesis "representative" instances, so the
fixed ALNS can be compared directly with the recorded thesis results on exactly
the same data.

| Project       | Scale  | Instances                      |
| ------------- | ------ | ------------------------------ |
| Multi-period  | small  | `dataset_12`, `dataset_30` |
| Multi-period  | medium | `dataset_13`, `dataset_26` |
| Multi-period  | large  | `dataset_3`                  |
| Single-period | small  | `dataset_1`, `dataset_3`   |
| Single-period | medium | `dataset_1`, `dataset_3`   |
| Single-period | large  | `dataset_1`                  |

The ALNS time budgets match the thesis (small 180 s, medium 360 s, large
720 s) so the comparison is like-for-like. Single-period CPLEX budgets are
recorded per run; each result stores the exact wall time, incumbent, best
bound, and solver status.

## Reproduce

From the portfolio root, with the shared `uv` environment activated:

```powershell
# Multi-period: 4 ALNS variants on 5 instances (writes results/multi-period)
.\.venv\Scripts\python.exe multi-period-delivery\experiments\run_portfolio_experiments.py `
  --results-dir results\multi-period --workers 6
.\.venv\Scripts\python.exe multi-period-delivery\experiments\build_portfolio_report.py

# Single-period: heuristic + CPLEX Python API (writes results/single-period)
.\.venv\Scripts\python.exe single-period-delivery\experiments\run_portfolio_experiments.py `
  --results-dir results\single-period --workers 3
.\.venv\Scripts\python.exe single-period-delivery\experiments\build_portfolio_report.py
```

## Headline results

**Multi-period.** On the metric the thesis actually published (fixed vehicle
cost), the fixed ALNS beats the archived thesis ALNS on **20 of 20** runs
across the five instances and four variants, with a mean fixed-cost reduction
of about 209 units. The thesis objective silently omitted the minimum-load
penalty because its penalty factor defaulted to zero; the corrected objective
adds that penalty, and the fixed ALNS is also better there on every run. See
`multi-period/README.md` for both tables.

**Single-period.** The route-local CPLEX Python API model proves optimality at
15.06 on the small `dataset_3` instance and reaches a 0.27% gap on the other
small instance. It also produces feasible incumbents on the medium and large
instances, replacing the earlier no-solution and out-of-memory outcomes. See
`single-period/README.md` for the exact objectives, bounds, gaps, and times.

The per-project README files are regenerated by the `build_portfolio_report.py`
scripts each time the experiments are re-run.
